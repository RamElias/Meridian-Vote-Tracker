# AI usage

Codex (GPT-6) was used as an implementation partner to inspect the assignment PDFs and project decisions, design and implement the API/Worker flows, write PostgreSQL migrations and OpenAPI documentation, and update project documentation. The appendix PDF was treated as illustrative; the primary assignment requirements took precedence.

AI-assisted code was checked by building the .NET 8 API and Worker images, running Docker Compose with PostgreSQL and Angular/Nginx, running the PostgreSQL and CSV parser smoke executables and Angular unit tests, and exercising CSV import, role-restricted vote positions, asynchronous snapshot calculation, per-country contribution details, and snapshot publication through the HTTP API and Angular UI. The CSV parser smoke initially failed because it treated a malformed row in the supplied input as impossible; it now asserts that the five-field row is preserved and parsing resumes. These checks also exposed fixes for PostgreSQL data-modifying CTE visibility, Npgsql array parameter typing, the nullable filter type in the conflict-list query, and a 30-second CSV validation timeout. Vote/ballot contradiction checks now use min/max comparisons and a longer command timeout. The supplied Q1 rev2 file completed with 5,960 rows (378 new, 5,576 unchanged, 6 country-vote conflict rows); a repeated upload was recorded as a duplicate linked to the successful import. An initial attempt failed at the default timeout and remains visible in import history; the successful retry is reported separately. Conflict acceptance, merging a second source proposal, and HTTP 409 on a second decision were verified. Snapshot contribution rows remained identical after a temporary position change and restoration. Replacing the published 2024 Q1 snapshot marked the former snapshot superseded and retained it in history. Angular tests cover navigation, import counts, and publication status; the UI was checked to show the new publication as active and the prior one as superseded.

No AI model or document extraction service is used by the application at runtime. PDF extraction remains out of scope until the core application is complete.

During a later scale check, `assembly_historic.csv` (103.6 MB, 962,171 data rows) was imported against a fresh, isolated Docker Compose PostgreSQL instance. The first attempt staged all rows but promotion hit Npgsql's default 30-second command timeout. Bulk promotion/report queries were given a 10-minute timeout; the retry completed with 962,109 new rows, 30 duplicates, and 32 invalid rows. The isolated containers and test volumes were removed afterward. A full-history ranking calculation was not exercised.


On 2026-10-23, a second requirements/code review used Codex to address import crash consistency, deferred report refresh, initial/unchanged provenance, exact ballot validation, snapshot progress locking, publication races, optimistic position concurrency, normalization traceability, generated DTO drift and contribution selection races. The Angular UI was split into four standalone screen components sharing a state service. SQL migrations protect approved versions, audit records and completed snapshot data; an ownership lock guards single-Worker startup recovery.

Verification used the .NET 8 SDK in WSL and an isolated PostgreSQL 16 container, plus a separate Docker-only test Compose project. Regression checks start an actual HTTP API, verify role enforcement and response contracts, cancel calculations before commit, and kill/restart an actual Worker while rejecting a competing instance. Five Angular tests passed, including rendered late-response checks. A synthetic 6,500-vote/150-country snapshot completed with 975,000 contributions and independently observable progress. Tests exposed a missing correlation header after exception handling cleared response headers; the header now uses OnStarting. They also exposed generated DTO requirements missing from test fixtures. The historical CSV benchmark and exact final results are recorded in VERIFICATION.md; no unrun Azure connectivity checks are claimed.

The final full-data check imported the supplied historical file successfully (962,171 rows: 962,109 New, 30 Duplicate, 32 Invalid). Upload/staging/validation/atomic promotion/report took 1,372.3 seconds while other verification ran. The resulting 6,480-vote historical snapshot completed with 972,000 contributions in 358.0 seconds. All temporary databases and test containers were then removed. These times are local measurements under concurrent verification load, not production performance guarantees.
